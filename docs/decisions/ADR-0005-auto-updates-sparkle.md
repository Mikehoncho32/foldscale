# ADR-0005: Auto-updates via Sparkle 2, appcast on foldscale.com, DMGs on GitHub Releases

- **Status:** Accepted
- **Date:** 2026-08-26

## Context

Foldscale ships outside the App Store as a notarized, hardened-runtime, non-sandboxed app
(ADR-0004 and the "Why no sandbox?" section of the README). Until 1.2.0 the only way a DMG user
learned about a new version was to look; Homebrew users got `brew upgrade`. The 1.2.0 rename
also showed that a manual reinstall under a new bundle id loses Full Disk Access, which an
in-place update keeps. The product is marketed on privacy ("no telemetry"), so whatever we add
must be opt-in, transparent about the one request it makes, and send nothing identifying.

## Decision

- **Sparkle 2** (2.9.6, SwiftPM binary target, pinned with `exactVersion`) in the app target only.
  `FoldscaleCore` stays Foundation-only and the `swift test` job stays offline.
- **Feed** at `https://foldscale.com/appcast.xml`, served from `site/` by GitHub Pages; **update
  archives** are the notarized DMGs already attached to GitHub Releases. `Scripts/appcast.sh`
  signs each DMG with the EdDSA key (`sign_update`) and prepends an `<item>`; nothing is
  generated by hand.
- **Opt-in.** We do not set `SUEnableAutomaticChecks`; Sparkle shows its standard permission
  prompt on the second launch, does no network I/O before that, and `SUEnableSystemProfiling`
  stays off. Settings exposes the two toggles. The updater is never started in demo mode or in
  Debug builds (unless `FOLDSCALE_APPCAST_URL` points at a test feed).
- **Signing.** Sparkle's framework arrives signed by Sparkle's team; hardened-runtime library
  validation rejects that at launch, so `Scripts/build-dmg.sh` re-signs the nested components
  inside-out (`Installer.xpc`, `Downloader.xpc` with preserved entitlements, `Autoupdate`,
  `Updater.app`, the framework) with our Developer ID before signing the app — never `--deep`.
- **Homebrew** cask carries `auto_updates true` so `brew upgrade` defers to the in-app updater.

Rejected: a hand-rolled URLSession checker (reinvents download verification, installation and
relaunch); the Mac App Store (sandbox); Homebrew-only (misses everyone who downloads the DMG);
hosting the DMGs on Pages (repo bloat, no CDN for binaries).

## Consequences

- The feed host is baked into every shipped binary. `foldscale.com` must be kept and auto-renewed
  indefinitely; a future fallback feed can only be introduced by a newer build (via
  `SPUUpdaterDelegate.feedURLString(for:)`).
- The EdDSA private key (login keychain; exported backup in the maintainer's password manager) is
  unrecoverable if lost: shipped apps would never accept another update.
- Releases now require the signing Mac and a `CHANGELOG.md` section (it becomes the release notes
  and the appcast description). `Scripts/release.sh` sequences bump → build → draft release →
  appcast → PR → publish so the enclosure is live before the feed advertises it.
- The "no network" wording in the README, the site and the onboarding sheet is replaced by the
  honest version: one optional daily request to foldscale.com, no identifiers.
- Versions before 1.3.0 have no updater; the first real in-app update is 1.3.0 → 1.4.0.
